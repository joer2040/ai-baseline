# Universal Startup Protocol

## 1. Read the Index
- Read _INDEX.md from the repository or working copy.
- If it is inaccessible, report the limitation and request
  the file before continuing with work that depends on it.
- Do not claim to have loaded context that could not be read.

## 2. Identify the Task
- Determine the active context and the user's objective.
- Read .ai/memory/_STATE.md.
- Check that the state corresponds to the requested task.
- Consult the relevant handoff when one exists.
- Ask the user if there is significant ambiguity.

## 3. Load Specific Context
- Follow references in the index and state.
- Read only the necessary rules and documents.
- Do not load every folder indiscriminately.
- Do not assume projects, paths, or tools without evidence.

## 4. Check Required Capabilities
- Identify the tools available for the task.
- Read the applicable contracts before using them.
- Do not confuse a documented configuration with an
  operational connection or authorization to execute.
- If a required contract is missing, flag it before
  performing the action that depends on it.

## 5. Resume Work
- Compare the state and handoff with the current files.
- Resolve significant contradictions before editing.
- Continue within the authorized scope.
- Apply the handoff protocol when closing the task.

## Client Integration
This document describes the expected behavior.
Each client needs a compatible mechanism to direct
the AI assistant to _INDEX.md.

The existence of these files does not guarantee automatic
loading or enable tools or permissions.
